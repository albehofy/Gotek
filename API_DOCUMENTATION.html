Gotek Digital Solutions — Backend API Spec
This document defines all REST API endpoints required by the Gotek website frontend. The frontend is already built and integrated — it calls these endpoints and gracefully falls back to rich dummy data when any endpoint is unavailable.

⚙️ Base URL & Configuration
Configure the base URL in api.js inside the API_CONFIG object. All endpoints are relative to this base.
// api.js — API_CONFIG
const API_CONFIG = {
  BASE_URL:      'https://api.goteksa.com/v1',  // ← Set your backend URL here
  TIMEOUT_MS:    5000,                       // 5s timeout then fallback
  RETRY_ATTEMPTS:2
};
CORSYour backend must return CORS headers allowing https://gotek.sa and http://localhost:* for development.
🔐 Authentication
The public endpoints (GET requests) require no authentication. The contact form POST should be protected against spam via rate limiting and/or reCAPTCHA. If you add private admin endpoints in the future, use Bearer token authentication.
// Headers expected for public endpoints:
Content-Type: application/json
Accept: application/json

// Future admin endpoints should add:
Authorization: Bearer <token>
❌ Error Handling
All error responses must use the following format. The frontend handles errors gracefully — if an endpoint fails, it falls back to dummy data automatically.
{
  "success": false,
  "error":   "Human-readable error message",
  "errors":  { "field_name": "Validation message" }  // for 422
}
HTTP CodeMeaningWhen to Use
200SuccessRequest succeeded, return data
404Not FoundProject ID does not exist
422Validation ErrorContact form has invalid fields
429Rate LimitedToo many requests from same IP
500Server ErrorUnexpected backend failure
GET /projects — Portfolio List
Returns a paginated, filterable list of portfolio projects. Used on the Portfolio page grid and the Home page preview section.
GET /v1/projects Portfolio list with filtering ›

Query Parameters:

ParameterTypeDefaultDescription
page optionalinteger1Page number for pagination
limit optionalinteger9Items per page (max 50)
category optionalstringallFilter: all | branding | ads | web | video | pos | social
featured optionalboolean—If true, return only featured projects

Example Request:

GET /v1/projects?page=1&limit=9&category=branding

Response 200:

{
  "success": true,
  "data": [
    {
      "id":           "al-nakheel",         // URL slug — must match project detail ID
      "title":        "Al-Nakheel Construction",
      "titleAccent":  "Brand Identity",       // subtitle shown on card hover
      "category":     "branding",             // used for filter buttons
      "tags":         ["Branding", "Visual Identity", "Print"],
      "client":       "Al-Nakheel Group",
      "year":         "2025",
      "thumbnail":    "https://your-cdn.com/projects/al-nakheel/thumb.jpg",
      "thumbBg":      "linear-gradient(135deg,#FDDCCA,#F5AA80)", // fallback if image fails
      "emoji":        "🏗️",                   // shown if no thumbnail
      "featured":     true
    }
  ],
  "pagination": {
    "page":       1,
    "limit":      9,
    "total":      24,
    "totalPages": 3
  }
}
Image HostingThumbnails should be 800×600px WebP, hosted on your CDN. The frontend also accepts Unsplash URLs. If thumbnail is null or fails to load, the CSS gradient + emoji fallback is shown automatically.

POST /contact — Submit Inquiry
Receives contact form submissions from the Contact page. Should store the inquiry in the database and send a notification email to the Gotek team. Rate limit to 5 requests/IP/hour.
POST /v1/contact Submit contact form ›

Request Body (application/json):

FieldTypeValidation
name requiredstringMin 2 chars, max 100
email requiredstringValid email format
phone requiredstringMin 9 chars (intl format accepted)
service requiredstringOne of the 6 service IDs
message requiredstringMin 10 chars, max 2000
company optionalstringMax 100 chars
budget optionalstringBudget range string

Example Request:

POST /v1/contact
Content-Type: application/json

{
  "name":    "Ahmed Hassan",
  "email":   "ahmed@techmart.sa",
  "phone":   "+966501234567",
  "company": "TechMart Retail",
  "service": "Paid Advertising",
  "budget":  "10,000-30,000 SAR",
  "message": "We need help with our Meta and Google campaigns. Current ROAS is terrible."
}

Response 200 (Success):

{ "success": true, "message": "Thank you! We'll be in touch within 24 hours." }

Response 422 (Validation Error):

{
  "success": false,
  "errors": {
    "email": "Invalid email format",
    "phone": "Phone number too short"
  }
}
IMPORTANTThe frontend shows a loading state on the submit button while waiting for this response. If the API times out (5s), it shows a simulated success for demo purposes. In production, replace this with proper error UX.
Notification EmailWhen a submission arrives, send an email to hello@goteksa.com with all field values formatted clearly, and an auto-reply to the client confirming receipt.

📋 Consistent Response Format
Every response from every endpoint must follow this envelope format. The frontend checks success: true before using data.
// Success
{ "success": true,  "data": <array or object> }

// Error
{ "success": false, "error": "Message", "errors": {} }

// Paginated list
{ "success": true,  "data": [], "pagination": { "page":1, "total":24, ... } }
🛡️ Fallback & Dummy Data
The frontend (api.js) automatically falls back to the built-in dummy data if any endpoint is unavailable, times out, or returns a non-200 status. This means the website always works — even during backend development. You can build endpoints incrementally.
Build Order RecommendationStart with: (1) GET /projects, (2) GET /projects/:id, (3) POST /contact — these three are the most critical for the user experience. The others can be added later.
Dummy Data LocationAll dummy data is defined inside api.js in the DUMMY_DATA object. This includes 9 full projects, 6 testimonials, 6 team members, stats, and all 6 services.
